# Project Overview

GenesisEngine is a C++20 engine/editor workspace targeting Windows, MSVC, SDL2, Vulkan, ImGui, Assimp, fmt, EnTT, yaml-cpp, SPIR-V reflection, Vulkan Memory Allocator, and vk-bootstrap.

The workspace is generated by Premake. Generated Visual Studio solution and project files may exist locally, but they are machine/worktree artifacts and should not be treated as source of truth.

## Repository Layout

| Path | Role |
| --- | --- |
| `premake5.lua` | Root Premake workspace definition. |
| `premake_cfg.lua` | Shared path, include directory, library directory, and third-party library configuration. |
| `Engine.lua` | Premake project definition for the `Engine` shared library. |
| `Editor.lua` | Premake project definition for the `Editor` executable. |
| `Assimp.lua` | Utility Premake project that drives CMake for Assimp. |
| `YamlCpp.lua` | Utility Premake project that drives CMake for yaml-cpp. |
| `Engine/` | Engine runtime, public API headers, renderer, assets, ECS, systems, scene, windowing, input, GUI, and utilities. |
| `Editor/` | Editor entry point, editor camera, project context, asset import helpers, ImGui editor windows, and test/editor systems. |
| `Resources/` | Editor/runtime resources such as shaders, compiled SPIR-V, fonts, and default assets. |
| `vendor/` | Third-party dependencies tracked as git submodules. |

## Workspace Projects

### Engine

`Engine` is configured as a shared library. It includes the engine source tree, ImGui source files, ImGui Vulkan/SDL backends, Vulkan Memory Allocator, SPIR-V reflection, and vk-bootstrap source files. It links against SDL2, Vulkan, Assimp, fmt, yaml-cpp, and Win32 system libraries configured in Premake.

Important source areas:

- `Engine/API/`: public umbrella headers for applications using the engine.
- `Engine/Core/`: entities, handles, components, component reflection, camera, and screen helpers.
- `Engine/Systems/`: base system type, lifecycle manager, transform system, GUI system, and test system.
- `Engine/Renderer/`: render system, render thread, renderer facade, render graph, render packets, Vulkan resources, and Vulkan backend.
- `Engine/Object/`: engine-side resource/object types such as mesh, texture, and material.
- `Engine/Assets/`: asset system, async request tracking, Assimp/STB loading, metadata-aware asset resolution, and asset artifact handling.
- `Engine/Scene/`: scene model, scene system, serializer, scene manager, and mesh-asset-to-scene importer.
- `Engine/Window/`: SDL window ownership and window system.
- `Engine/Gui/`: ImGui backend and base GUI window.
- `Engine/Input/`: SDL input polling and frame input state.
- `Engine/JobSystem/`: job handles, worker threads, and async job execution.
- `Engine/Utils/`: path, time, random, transform, and filesystem compatibility helpers.

### Editor

`Editor` is configured as a console application that links against `Engine.lib`. It creates an engine instance, resolves project/resource roots from command-line arguments, validates the project layout, registers editor-specific systems, and registers ImGui windows.

The editor currently registers:

- `TestSystemExternal`
- `EditorCameraSystem`
- `DockingRoot`
- `SceneHierarchyWindow`
- `InspectorWindow`
- `SceneViewWindow`
- `ProjectFilesWindow`
- `ProfilerWindow`
- `IconBrowserWindow`
- `TestEditorWindow`
- `SystemViewer`

### Utility Projects

The `assimp` and `yaml-cpp` Premake projects are utility targets. They create build directories, run CMake, build Release binaries, and copy the resulting libraries/DLLs into the configured output directory.

## Third-Party Dependencies

The tracked submodules are:

- `vendor/fmt`
- `vendor/vk-bootstrap`
- `vendor/ImGui` on the `docking` branch
- `vendor/entt`
- `vendor/assimp`
- `vendor/yaml-cpp`

The configuration also references optional or embedded dependencies such as ImGuizmo, spirv_reflect, SPIRV-Cross, Vulkan Memory Allocator, and STB.

## Generated and Local Artifacts

The `.gitignore` excludes generated Visual Studio files, `bin`, `bin-int`, `.vs`, and `.dotnet-home`. Local generated files may still exist in a working tree, but they are not part of the tracked source surface.
